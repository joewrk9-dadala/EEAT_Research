# 文章審核流程與結果

本專案用 8 個 prompt，審核文章的證據使用、模擬揭露、風險及內容完整性，再產出修訂稿與成果報告。

## 輸入與流程

- `article`：原文，保留為 V0。
- `common`：每個階段都要注入的共用規則。
- `boundary`：證據邊界，限制可以下的結論。
- `user_story`：虛構情境素材，不是真實個案證據。

`prompt1～6`：建立規則 → 拆解主張 → 初審 → 查證 → 修訂 → 複審。未通過時回到查證或修訂，最多 3 輪。

`prompt7`：設計或分析流程比較測試。`prompt8`：整理實際成果。

## 本次結果

**完成 1 輪修訂，V1 通過本專案內容驗收。** 原稿已具備主要查核步驟，未發現致命或重大問題；本次修正 3 項一般問題：

| 修改重點 | 處理方式 |
| --- | --- |
| 主題與使用情境不夠明確 | 補明娛樂城主題，以及桌面讀者如何使用手機示例。 |
| 截圖的「證明」措辭過強 | 改為協助核對畫面，並確認來源、編輯情況與事件時間。 |
| 介面改善效果未經測試 | 改成設計建議與角色偏好，不宣稱已證實有效。 |

修訂後保留感官描寫、事件對應、帳務計算與具體客服提問。正文由 **3,149 增至 3,464 漢字**，不含標題與表格，包含模擬聲明及文內客服草稿。原始檔案未修改。

流程 7 已完成 **12 個測試案例草案**，尚未執行比較實驗或人工評分；流程 8 已完成成果報告。因此，目前能確認本篇完成修訂，還不能證明整套提示詞鏈的效果。
